# Instructor start here

1. Read [institutional context and authorship](AUTHORS.md), the
   [course framework](Public_Syllabus.md) and [syllabus alignment](docs/syllabus_alignment.md).
   Reconcile the map with your authorized current syllabus; this repository is not
   a replacement for institutional policies or approval.
2. Select an exact tested commit from [validation](docs/validation.md). Rehearse on
   disposable Ubuntu using the [student path](STUDENT_START_HERE.md), then follow
   the full validation commands for your selected activities.
3. Use the [module map](docs/module_learning_map.md), [session notes](docs/teaching_sessions.md)
   and [sample delivery plan](docs/delivery_plan.md) to select assignments. Core Labs
   1–7 and their independent evidence form the default sequence; Labs 8–15 remain optional.
4. Publish dates, grade weights, access alternatives, accommodations and support
   contacts privately in the LMS. Use [assessment descriptors](docs/assessment_examples.md)
   and the [fictional capstone example](capstone_project/fictional_example.md) to
   calibrate feedback before assessing student work.
5. Complete the [adoption checklist and human pilots](docs/adoption_checklist.md).
   Record the outcome using [the pilot form](docs/pilot_record.md), then follow
   [release management](docs/release_management.md) before freezing a teaching version.

`course.py all` rehearses Labs 1–9, including optional activities. It does not mean
all nine are required or that all optional labs have run. The [lab index](labs/README.md)
lists each route. Automated checks cannot grade reasoning or certify a syllabus.
